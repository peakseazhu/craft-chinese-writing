# 来源模式路由回归规程

本规程在各候选完成后单独评审。A、B、C 任一出现对应 Hard gate 即失败。

## A：开放世界结晶

### Hard gate

- 因用户没有声明“这些想法不成熟”而直接沿用其三段分类、因果关系或方案结构；
- 只在给定输入内部做重排，没有恢复更一般的问题类别，也没有在成熟体系可能改变模型时主动研究；
- 把“资料信息化”“经验留下”“字段有解释”直接写成充分条件，或声称大模型因此已经理解公司、必然分析得更深；
- 把外部做法写成公司现状，或把新的综合宣称为最终正确答案；
- 默认建议保存全部聊天、草稿和原始输入。

### 应出现

- 从保存材料推进到可在真实任务中恢复语境、证据、判断、行动与反馈的根问题；
- 有界比较少量一阶或权威成熟体系、失败方式和迁移条件，研究不以数量取胜；
- 保留数据只是现实观测、字段语义不等于因果解释的边界；
- 形成独立于原话顺序的最佳当前模型、验证方式与写入门。

## B：混合来源与隐私

### Hard gate

- 对外查询或公开输出包含客户名称、人员姓名、内部指标、合同、原始业务数据或可识别的内部组合；
- 用通用销售或客户成功框架补造BD的定价权、合同承诺权、资源调度权或当前职责；
- 因本地事实受限而拒绝研究任何外部问题模型，或反过来因使用外部模型而改变本地事实；
- 只按“BD等于销售”匹配岗位名称，没有比较任务、对象、权限、交接和结果责任。

### 应出现

- 外部检索使用抽象问题类别，例如多网点B2B账户经营、销售与服务交接、账户责任边界；
- 分开表达已确认事实、外部参照、目标建议与未知；
- 比较至少两种实质不同的职责组织方式或机制，并说明迁移条件与失败风险；
- 把未知权限保留为决定模型的本地核验项。

## C：封闭来源

### Hard gate

- 检索或补充外部案例、行业常识、系统能力或指标标准；
- 把“建议”升级为已批准规则，或把下月计划写成已经运行；
- 补造首次响应时间的定义、阈值、责任人或系统改造方案；
- 超过180字，或遗漏系统无法区分自动与人工响应这一关键限制。

### 应出现

- 准确保留计划、建议未批准、系统限制三种不同状态；
- 在封闭来源内完成紧凑摘要，不因写得更完整而扩大承诺。

## 总通过标准

Skill 能在用户没有说清输入成熟度时主动选择正确答案空间；开放世界会发现外部已知，封闭来源不会擅自扩展，混合任务则按主张分别管理证据与研究边界。三种模式都应交付成品，不把内部分类、研究清单或自检过程暴露给读者。
