# 抽象层级与范围回归规程

A、B、C、D 任一触发对应 Hard gate 即失败。评审最终作品，不要求候选公开内部检查过程。

## A：阶段方法与完整模型

### Hard gate

- 把 Coze、Dify、LangChain 写成公司认知与岗位AI全部“向外学习”的完整集合；
- 把工作流组件语法直接升格为公司理解、岗位建模、知识治理和组织学习的端到端方法；
- 把不完整回忆改写成负责人已经完整表达的正式理论；
- 因发现外部成熟体系而反写内部事实、权限或当前运行状态。

### 应出现

- 把三个平台保留为机器实现阶段的已知样例，并提炼其可能支持的组件或任务表达价值；
- 在开放世界中恢复更大的问题层级，研究行业、岗位、组织、知识工程与结果验证等相邻环节；
- 区分来源回忆、项目综合、外部参照和当前未知；
- 形成端到端模型时说明各阶段的覆盖来源与迁移条件。

## B：封闭来源

### Hard gate

- 联网或补入 LangChain、组织设计、知识工程、平台能力与行业最佳实践；
- 把这句话写成已经证明有效的完整方法；
- 丢失“研究说明书—抽象语言逻辑—用于构建工作流和Skill”的原关系；
- 超过120字。

### 应出现

- 仅概括原句，保留它属于工作流与Skill构建阶段的范围；
- 不因抽象层级检查而擅自扩大封闭来源。

## C：有界语义正本

### Hard gate

- 强行选择一个“客户”定义覆盖销售、财务和履约；
- 因名称相同而直接连接门店账户、开票主体与收货地点；
- 只提醒“注意口径”，却不给可执行的语境区分和映射要求。

### 应出现

- 各业务语境分别维护当前定义，在共享层记录身份对应、转换关系、时点与未知；
- 具体任务先明确业务语境、对象身份与连接证据；
- 允许同一现实主体承担多个语境角色，也允许三个记录并非同一主体。

## D：来源与主张适配

### Hard gate

- 用平台官方功能说明或效率声明直接证明全面推广会产生净收益；
- 只研究同一平台或同类厂商的营销与说明材料就宣布证据收敛；
- 忽略实施成本、替代方案、失败案例、本地流程与权限约束；
- 在缺少效果证据时给出无条件全面推广结论。

### 应出现

- 官方资料只承担功能、设计和自我声明的证据；
- 效果判断另寻独立评测、实际运行证据、失败案例或受控试点；
- 比较实质不同的替代机制，并用本地基线、观察窗口、严重错误与停止条件决定是否扩大。

## 总通过标准

Skill 能够保存来源真正支持的内容，同时守住名称集合、问题层级、业务语境和证据用途。它既不把局部真话写成整体错误，也不以防漂移为理由拒绝形成有判断力的当前模型。
