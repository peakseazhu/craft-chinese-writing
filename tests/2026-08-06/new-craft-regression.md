## C3

知识页的版本记录，首先要回答一个最直接的问题：这页知识目前得出了什么结论。读者来到页面时，需要先看见现在成立的认识，而不是先穿过一串变化才猜到落点。当前结论因此是版本记录的入口，也是另外两部分围绕的对象。

只有当前结论还不够。结论发生过变化时，读者还要能够回看它原来是什么、后来变成了什么。变化过程使“当前”不再像一个突然出现的答案。它保留了认识移动的方向，也让读者分清哪些内容仍然有效，哪些已经被后来的结论取代。版本记录在这里承担的不是重复展示多个结论，而是把它们之间的变化交代清楚。

每次变化还需要落到改变结论的证据上。没有这一步，读者虽然知道结论变了，却不知道变化凭什么发生。证据把变化和理由连接起来：读者既能检查当前结论的来路，也能在回看旧结论时，找到促使认识改变的依据。

这三点不能彼此替代。只写当前结论，读者看得到结果，看不到它怎样形成；只列变化，读者能追踪过程，却可能找不到现在应以哪个结论为准；写了当前与变化，却没有证据，版本之间的转折仍然无法复核。

因此，一份完整的版本记录应把三条线接在一起：以当前结论确定落点，以结论的变化保留路径，以改变结论的证据说明路径为何转向。读者由此可以先取得现在的答案，再按需要回到变化过程，最后找到相应证据。三项信息各有职责，也共同回答同一个问题：这个知识页现在为什么得出这样的结论。

调用方使用同步接口时，应把 JSON 请求发送到 `POST /v1/jobs`，并在请求中提供 `idempotency_key`。服务会根据同一个 key 所对应的 payload 是否完全相同，返回两种不同结果。

同一个 key 与完全相同的 payload 再次提交时，服务返回原来的 `job_id`，HTTP 状态码为 HTTP 200。同一个 key 与不同的 payload 一起提交时，服务返回 HTTP 409。判断结果同时取决于 key 和 payload，不能只比较其中一项。

请求示例如下：

```json
{"idempotency_key":"abc-123","payload":{"mode":"safe"}}
```

现有材料只说明上述两种情况，没有说明其他重试行为。因此，不能从这份说明推断其他重试请求会得到何种响应。更多限制见[重试规范](https://example.com/retry)。

## R8

一份决策记录首先要让读者看到当前决定。这个落点不能藏在过程后面，因为读者需要先知道现在以什么为准。当前决定写清以后，后面的内容才有共同对象：哪些道路没有被采用，哪些证据支持了现在的选择，以及什么情况会使它再次进入讨论。

接着要记录被放弃的方案及其理由。只保留当前决定，会让结果看起来像唯一可能的答案；列出其他方案，却不写放弃理由，又只得到一张没有判断关系的清单。方案和理由放在一起，读者才能看见选择发生在哪里，也能区分“没有采用某个方案”和“这个方案从此不再成立”。后一个判断不能仅由“曾被放弃”推出，因为重新讨论的条件还可能改变。

支持当前决定的证据，回答的是决定为什么在此刻成立。它与放弃理由有关，却不等于放弃理由的重复。放弃理由说明其他方案为何没有成为当前选择，证据则让读者找到当前选择所依据的材料。两者都可回看，当前决定才不只是一个孤立结果。

重新讨论的条件为这份记录划出边界。它说明当前决定在什么条件下需要重新打开，而不是把“当前”写成永远不变。条件没有出现时，读者知道现有决定仍是落点；条件出现时，读者也知道应当回到哪些证据和方案继续讨论。这样，变化不必抹去旧记录，旧记录也不会阻止新的判断。

三部分由此形成一条可以回看的路径：先找到当前决定，再检查被放弃的方案和理由，随后核对支持当前决定的证据，最后查看重新讨论的条件。当前决定负责给出答案，备选方案及理由保留选择过程，证据与重开条件共同交代答案的依据和边界。决策记录把这些关系写清，也就完成了它在给定材料内能够完成的工作。

就这组记录而言，五人团队不该从复杂分类法开始，关键不在“复杂”这个词听起来麻烦，而在分类先于实际资料形成得太快。第一周，团队设计了62个标签。标签数量是团队人数的12.4倍，这个比例本身不能证明方案失败，也不能说明标签由谁维护；真正值得看的是，标签进入使用以后发生了什么。

两周后，17个标签只被使用过一次，占62个标签的约27%。与此同时，还有11条资料没有标签。前一个数字说明一部分标签只与极少的现有资料发生联系，后一个数字说明已经建立的标签表没有覆盖全部资料。这两件事同时出现，至少表明第一周的分类规模没有自然转化为稳定、完整的实际使用。材料没有记录原因，因此不能把结果归结为成员不理解、不愿使用，或标签设计者判断失误。

第二次尝试改变了顺序。团队没有先扩充标签表，而是先维护6个仍在使用的主题页。一个月后，3个反复使用的主题从实际资料中稳定出现。这里最重要的不是把6和3包装成一套新的固定标准，而是主题的形成有了资料使用作为依据：先看哪些内容持续出现，再确认哪些主题值得保留。这个顺序减少了在材料尚未显出重复关系时就预先规定大量类别的需要。

但现有记录只允许把结论说到这里。它没有提供检索速度，所以不能声称第二次尝试让查找更快；没有成员满意度，不能说大家更喜欢主题页；也没有长期维护成本，不能断言复杂标签一定更费时或更贵。一个月后出现3个稳定主题，证明的只是这些主题在这段材料整理中反复出现，不等于知识库的长期效果已经得到验证。

我参与了资料整理，但没有设计第一次标签表。因此，我能依据的是两次尝试留下的数字和顺序，而不是标签设计时的考虑。对这个五人团队，较稳妥的起点是维护已经在用的少量主题，让分类从反复出现的资料关系中长出来。等到新的稳定主题实际出现，再把它纳入现有结构。这样的判断不需要把第一次尝试说成彻底失败，也不需要替第二次尝试预告尚未发生的效果。它只承认一件已经被记录下来的事：62个预设标签中出现了低频使用和资料未标记，而从6个在用主题页出发，一个月后识别出了3个反复使用的主题。
