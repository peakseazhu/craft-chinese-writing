# v2.2.1：守住从样例到完整模型的抽象层级

`v2.2.0` 让开放世界任务能够主动发现外部成熟体系，但仍留下一个更隐蔽的入口：某段材料在原范围内完全正确，写作者却在综合时把它放进更高层级的标题或方法。命名产品会被误读成完整比较集，机器实现阶段的方法会被压缩成整个项目的“向外学习”，主体自述也可能被用来证明效果和普适性。

`v2.2.1` 增加抽象升格门。

## 主要变化

1. 在任务合同、材料支持和最终修订中同时区分具体样例、局部模式、阶段方法和端到端模型。
2. 明确命名列表默认是已知样例集；只有定义了全集并证明覆盖，才可以写成完备清单。
3. 阶段方法升格前必须检查原问题层级、生命周期位置、对象、条件、相邻上游、下游、交接和责任。
4. 产品平台、当前组织图、岗位名单和数据结构只先作为实现、组织或观测载体，不能因其具体可见就成为问题本体。
5. 来源按主张选择：一阶材料确认主体的定义、设计与声明；效果、普适性和失败条件需要独立研究、运行证据或反例。
6. 研究停止条件增加来源家族差异，避免在同一类产品文档中得到虚假的“已经收敛”。

## 没有做什么

- 没有要求每篇文章展示内部层级标签或研究清单；这些仍是写作判断。
- 没有否定具体产品、案例和原始表达的价值；它们保留在能够证明的层级。
- 没有把外部成熟体系变成统一答案。成熟做法是基线与候选，本地方案也要和替代方案一起验证。
- 没有扩大封闭来源任务的材料范围。
