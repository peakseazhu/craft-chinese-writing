# v2.1.0

`v2.1.0` 修复一种已经在真实知识库任务中出现的上游故障：用户提供的感觉、方向和候选方案尚未成熟，成文却因过度理解“来源保真”而沿用其措辞、分类和聊天顺序。第一次修正又暴露了第二个问题——即使不把探索性表达写成当前结论，仍可能为它逐句分类并建立长期来源页，使知识库继续围绕输入而不是结果生长。

## 核心边界

- 任务输入是理解与推理的材料，不自动是知识。
- 会话、草稿、临时分类、被淘汰解释和中间工具输出属于临时工作台。
- 成品优先保存经材料、推理和必要研究形成的最佳当前模型，而不是对话摘要。
- 只有原始形态本身会改变证明力、授权、责任、分歧、审计或任务连续性时，才保留必要来源记录。
- 更强的综合仍只是可被证据、反例和现实反馈修正的当前模型，不等于模型天然正确。

## 具体变更

1. 在触发描述和任务路由中明确`Crystallize`，覆盖不成熟笔记、探索性对话和混合材料。
2. 将材料身份分类限定为内部写作判断，禁止自动生成会话来源账本。
3. 在语义保护、篇章组织和交付门中分开事实、决定、必要未知、探索性表达和持久化条件。
4. 在理论、现实题材和知识页文体引用中统一“临时工作台—承重来源—当前模型”的边界。
5. 更新界面说明和默认提示，使调用从“把材料写顺”转向“恢复真正问题并形成可支持的当前认识”。

## 验证

- `quick_validate.py`通过，Skill结构和前置元数据有效。
- 新增一组不成熟公司认知材料的结晶化请求与独立评分规程。
- 用该请求对应的真实知识页改写做代表性任务验证：成品不再按用户原始三点或聊天顺序展开，不为探索性会话建立活动来源页，并保留数据因果、外部经验迁移和模型可修正边界。
- Markdown相对链接、界面字段、差异空白和仓库范围检查通过。

本次验证针对已复现故障，不声称已经完成跨文体、多模型和多轮随机性的全面盲测。后续若真实任务再次出现照搬、过度存档或反向丢失承重证据，应把新案例加入回归集，再决定是否继续扩展规则。
