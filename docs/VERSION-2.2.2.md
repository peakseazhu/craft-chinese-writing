# v2.2.2：让正确的结晶能力先被选中

`v2.2.1`已经能在Skill运行后守住样例、局部模式、阶段方法与端到端模型的边界，但仍有一个运行前旁路：发现描述先强调通用改稿，真正区分本Skill的“高熵材料结晶、第一性原理和当前模型”出现在后面。当运行环境同时提供通用中文长文或活人化Skill时，路由器可能在完整读取本Skill前就选错入口，使后续抽象升格门根本没有机会执行。

`v2.2.2`修复的是选择层，不改写`v2.2.1`已经建立的认知方法。

## 主要变化

1. 把“不完整笔记、探索性对话和混合来源结晶为可支持的当前模型”前置为description的首要能力。
2. 把第一性原理、知识页和业务当前模型放到通用改稿、润色与去AI味之前，降低长描述被截断时的误路由风险；可见默认提示仍先判断封闭、开放或混合来源，避免前置结晶触发变成无条件外部研究。
3. 在运行规则中明确：来源治理、认知结晶和抽象层级由本Skill承接；内容模型已经稳定、主要追求特定叙事形态或中文互联网语气时，才选择相应的通用写作Skill。
4. 明确两套通用写作默认值不自动叠加，避免一套Skill的禁令或文体偏好损坏另一套Skill的证据与作品合同。
5. 增加确定性合同检查，验证版本、发现描述、`openai.yaml`和分流回归材料保持一致。

## 没有做什么

- 没有声明本Skill适合所有中文写作；小说、主要创意写作、逐字转写、翻译和纯数据输出仍在边界之外。
- 没有否定通用中文叙事与活人化Skill。两者解决的主要问题不同，正确做法是分流，不是互相吞并。
- 没有用结构脚本代替语义评测。脚本只能发现已知机械断裂，真实输入仍需检查最终模型、来源身份和文章效果。
